# Six-Ball Review — interface notes

The static interface turns the generated evidence snapshot into a manual bowling-review worksheet. It searches player names or Cricsheet IDs, keeps each phase distinct, and displays observed rates, regularized rates, conditional bootstrap bands, sample size, reference contrasts, sensitivity checks and source-match identifiers. The alphabetical list has no ranking score.

## Run locally

Use Node.js 20 or newer. There are no runtime packages to install.

```sh
npm start
```

Open `http://127.0.0.1:4182/`. The server binds only to loopback and serves `dist/`; analysis files outside that folder are not exposed. Serve over HTTP or HTTPS rather than opening `index.html` directly. The interface fetches `data.json` and uses Web Crypto to fingerprint the exact bytes it received.

```sh
npm test
```

The Node test runner covers the UI model and local static-server boundaries. Python analysis/profile tests and reproduction instructions are documented separately in [README.md](README.md) and [VALIDATION.md](VALIDATION.md).

## Working with the review sheet

- Choose a phase, search a player and inspect the evidence. Filtering selects a matching profile; zero results hide the detail panel.
- Add one to three cases manually. Cases can come from different phases; the sheet keeps each case's own phase and does not compute a cross-phase ranking or pairwise inference.
- Edit a review question and optional note. Changing phase, search, evidence filter or inspected player preserves selected cases and their text. A fourth case is rejected without evicting an existing one.
- Download readable HTML or exact JSON. The HTML is standalone and printable. JSON preserves complete selected profile fields, checks, source matches, frozen evaluation, method, attribution and fingerprints. A blank review question blocks export and receives keyboard focus.

Notes live only in the current tab's memory. There is no account, cloud sync, local-storage persistence or import feature. Export before closing or reloading; the browser is asked to warn about unexported selected cases. A download request cannot prove that the user retained the file. Notes typed after an export need another export.

## Interpretation

The profiles describe the fixed 2023–2025 first-innings cohort. The cohort is retrospective and partly uses later chase information. The separate 2026 evaluation is displayed from the frozen data, with its small Brier difference and limitations; the frontend does not rerun the model.

Insufficient evidence remains visible, including the pooled fallback for a player with no history in a phase. “Enough for review” describes operational sample thresholds. “Reviewable” describes the specified reference checks and does not mean better performance. Reference contrasts use percentage points. Sensitivity deletion ranges are not confidence intervals: leave-one-match-out is a collection of single-match removals, while dominant-venue removal is one group removal that also affects the reference population.

A review question is a prompt for subsequent investigation. Neither a selection nor a note proves footage was watched, coaching helped, a player is intrinsically superior, or a lineup should change. This interface does not recommend betting or make causal claims.

## Files and implementation boundaries

- `dist/index.html`, `styles.css`, `app.js` and `icon.svg`: original static presentation and interaction code; system fonts and no third-party runtime assets.
- `dist/ui-model.js`: filtering, selection, validation, formatting and export functions.
- `dist/data.json`: generated by the Python profile producer; the UI consumes it without recalculating evidence or changing thresholds.
- `tests-ui/`: tests using the real generated snapshot, plus explicit invalid-input mutations and synthetic QA notes.
- `server.mjs`: read-only local server for `dist/`.

The UI renders names and notes using DOM text, and escapes text in standalone HTML exports. A restrictive content-security policy is included. It makes no note uploads and includes no analytics. These are implementation controls, not a claim of a comprehensive security audit.
